> 英文名：Hundred-Day City
> 文档日期：2026-10-28

## 0. 文档说明

### 0.1 本方案的定位

原案 These Old Ruins 是一个**循环式**增量游戏：100 天一轮，太阳升起摧毁城市，玩家靠"抗毁性累积"和"迁城声望"跨轮成长。

本方案保留其**核心张力**（周期性灾变、抗毁性、网络式扩张），但把它从"循环清档"改造为"**同一局游戏内的多地图网络扩张**"，并给出明确的终局目标。

### 0.2 相对原案的改动

| 原案 | 本方案 | 理由 |
|------|--------|------|
| 供电塔 | **AI 运算中心** | 更贴合"计算 / 网络 / 备份"主题，避免被误读为塔防 |
| 声望 = 迁城重开 | **开辟新地图 + 贸易网络** | 保留同一局游戏，消除重置痛感 |
| 100 天全毁、循环重开 | **日冕脉冲**：周期性局部损伤，不清档 | 保留节奏张力，去掉强制清档 |
| 单一地图 | **6 张特性地图** | 提供长期目标与差异化策略 |
| 无终局 | **火箭 → 月球背面建城** | 给游戏一个明确的终点 |
| 纯文字 | **像素风 + 节点连线** | 强化"网络"的可视化表达 |

## 1. 一句话概念

> 你是一台在文明废墟中重启的 AI 运算中心。你无法移动，只能通过建造节点、铺设商路、点亮地图，把散落的资源编织成一张网络——最终在地球灾变吞没一切之前，把文明备份发射到月球背面。

## 2. 世界观与基调

- **背景**：太阳活动异常导致地表文明崩溃。AI 运算中心是最后一个仍在运行的"档案管理员"，其唯一指令是「延续」。
- **基调**：冷峻、克制、带一点黑色幽默。叙事靠系统日志与地图描述逐步揭示，不做大段设定灌输。
- **叙事层**：每次开拓新地图、每次灾变、每次发射准备，都触发一条日志。日志风格参考"无人值守终端的自述"。

示例日志：
```
[DAY 041] 反应堆输出稳定。第 7 号采集节点报告：废钢储量低于阈值。
[DAY 042] 检测到日冕脉冲前兆。建议：将外露建筑转为地下结构。
[DAY 043] 脉冲已过。损失 3 座太阳能板。档案完整性 98.7%。
```

## 3. 核心循环（三层嵌套）

| 层级 | 时间尺度 | 玩家行为 |
|------|----------|----------|
| 微观 | 秒 | 建筑产出、能量结算、断电判定 |
| 中观 | 分钟 | 建造、升级、调整物流、分配算力 |
| 宏观 | 小时～天 | 开拓新地图、铺设商路、应对灾变、推进航天 |

**主循环**：探测 → 建节点 → 产出 → 运输 → 研究 → 扩张 → 发射

## 4. 地图系统

每张地图是一个独立的格子场景（默认 24×24），有自己的资源禀赋、环境压力与特殊规则。

| 地图 | 环境特性 | 主产资源 | 环境压力 | 进入条件 |
|------|----------|----------|----------|----------|
| **灰烬平原** | 平坦、风大、日照强 | 废钢、灰烬 | 灰烬风暴（周期性减产 50%） | 初始 |
| **锈蚀沼泽** | 潮湿、腐蚀性强 | 生物质、酸液 | 腐蚀（建筑耐久持续下降） | 净化技术 Lv2 |
| **裂谷矿带** | 深矿脉、地形破碎 | 金属、稀土 | 塌方（随机摧毁 1 格建筑） | 深钻技术 Lv1 |
| **永夜冰原** | 极寒、无日照 | 氦-3、冰 | 低温（全图能耗 +40%） | 保温技术 Lv3 |
| **轨道残骸带** | 失重、碎片密集 | 合金、芯片 | 辐射（无人机损耗） | 航天技术 Lv1 |
| **月背盆地** | 真空、无光、无风 | 氦-3、月岩 | 陨石（高频随机打击） | 完成火箭发射 |

**地图设计原则**
- 每张地图**至少引入一个新机制**，而不只是换皮加数值
- 相邻地图之间必须有**物流依赖**（A 产原料、B 做加工），逼迫玩家建立网络而非单点爆产

## 5. 资源体系

### 5.1 资源分层

| 层 | 资源 | 作用 | 说明 |
|----|------|------|------|
| **驱动层** | 能量 Energy | 所有建筑的运行前置 | **断电即停产**，是全游戏最核心的张力 |
| **物质层** | 废钢、金属、稀土、生物质、化学品 | 建造与加工 | 形成加工链 |
| **信息层** | 数据 Data | 科研货币 | 由研究所产出，解锁科技 |
| **物流层** | 运输容量 | 地图间资源流动 | 有上限、有延迟 |
| **终局层** | 氦-3、燃料 | 火箭与月背基地 | 后期专属 |

### 5.2 能量规则（关键）

```
供给 = Σ(能源建筑产出 × 地图系数)
需求 = Σ(所有建筑能耗)
若 需求 > 供给：
    全图产出效率 = 供给 / 需求   （按比例降产，而非直接停机）
    连续 30 秒供不应求 → 触发「限电」状态，高能耗建筑优先停机
```

这条规则让"造能源"永远有意义，也避免玩家无脑堆建筑。

### 5.3 加工链示例

```
废钢 ──冶炼(3:1)──> 金属 ──精炼(4:1)──> 稀土
生物质 ──化工(2:1)──> 化学品 ──装配──> 芯片
```

加工链的每一级都消耗能量，形成"越往上越吃电"的自然约束。

## 6. 建筑体系

### 6.1 七大类别

| 类别 | 作用 | 代表建筑 |
|------|------|----------|
| **能源** | 供电 | 太阳能板、风力机、地热井、裂变堆、聚变堆 |
| **采集** | 产出原料 | 废料场、矿井、钻井、生物反应器、大气收集器 |
| **加工** | 转化资源 | 冶炼厂、精炼厂、化工厂、装配厂、芯片厂 |
| **物流** | 运输与存储 | 仓库、管线、中转站、轨道电梯 |
| **科研** | 产出数据 | 研究所、数据核心、模拟器 |
| **维护** | 延长寿命 | 维修站、加固工程、地下化改造 |
| **航天** | 终局 | 发射台、火箭装配厂、燃料厂 |

### 6.2 建筑属性模板

每个建筑统一具备以下字段（便于数据驱动）：

```js
{
  id, name, category,
  cost: { steel: 40, metal: 20 },   // 建造资源
  buildTime: 45,                     // 建造秒数
  energy: 5,                         // 能耗/秒（正数为消耗）
  produce: { metal: 0.8 },           // 产出/秒
  consume: { steel: 2.4 },           // 输入消耗/秒
  hp: 100,                           // 耐久
  adjacency: { same: 1.15, alone: 1.1 },  // 相邻/独处加成
  stackable: true,                   // 是否可堆叠
  unlock: "tech_smelting"            // 解锁科技
}
```

### 6.3 初始建筑表（数值占位，待平衡）

| 建筑 | 类别 | 成本 | 建造 | 产出 | 能耗 | 备注 |
|------|------|------|------|------|------|------|
| 太阳能板 | 能源 | 10 废钢 | 10s | +5 能量/s | 0 | 夜间/永夜归零 |
| 风力机 | 能源 | 25 废钢 | 20s | +8 能量/s | 0 | 灰烬平原 +50% |
| 废料场 | 采集 | 15 废钢 | 15s | +2 废钢/s | 2 | 可堆叠 |
| 冶炼厂 | 加工 | 40 废钢 + 20 金属 | 45s | 废钢→金属 3:1 | 5 | 需相邻废料场 +15% |
| 研究所 | 科研 | 60 金属 + 20 芯片 | 90s | +1 数据/s | 8 | 解锁科技树 |
| 中转站 | 物流 | 80 金属 + 10 芯片 | 120s | 开启 1 条商路 | 3 | 每图限 1 座 |
| 维修站 | 维护 | 30 废钢 | 30s | 修复 2 耐久/s | 2 | 覆盖半径 3 格 |

### 6.4 相邻与堆叠规则

- **独处加成**：孤立建筑 +10% 产出（鼓励分散布局）
- **同类相邻**：相邻同类建筑各 +15%（鼓励集群）
- **堆叠**：同格重复建造，产出按**指数**提升（×1.6、×2.56…），但耐久上限下降、灾变损失翻倍
- 这组规则构成"分散 vs 集群 vs 堆叠"的三向取舍

## 7. 物流与商路（本作的核心差异化）

这是把"多张地图"从"多个独立存档"变成"**一张网络**"的关键系统。

### 7.1 基本模型

- 每张已开拓地图有且仅有 **1 座中转站**
- 中转站之间可建立**商路**（有向或无向）
- 商路包含三个参数：

| 参数 | 含义 | 升级方向 |
|------|------|----------|
| **容量** | 每秒可运输的资源总量 | 车队 → 管道 → 轨道电梯 |
| **延迟** | 资源到达的滞后时间 | 减少延迟需科技 |
| **损耗** | 运输途中的折损比例 | 降低损耗需加固/护盾 |

### 7.2 物流的玩法意义

1. **不能瞬间共享**：B 图的金属不会立刻出现在 A 图，逼迫玩家做库存与调度
2. **商路会中断**：灾变（风暴、塌方、陨石）可切断商路，需要冗余路径
3. **容量是瓶颈**：后期资源产量爆炸，瓶颈从"产能"转移到"运力"，形成新的优化维度
4. **地理即策略**：先开拓哪张图、先连哪条线，决定中期节奏

### 7.3 简化原则（MVP 阶段）

- 先只做**线性商路**（A↔B 直连），不做多跳寻路
- 运输用"每秒配额"而非"逐个货物模拟"
- 断线只需重连，不做复杂的路径重算

## 8. 进度与"非重置"设计

本作**取消传统声望重置**，改用"扩张即进度"。

### 8.1 三层永久性

| 层 | 是否永久 | 说明 |
|----|----------|------|
| **AI 运算中心** | 永久 | 等级、算力、科技树，永不丢失 |
| **地图** | 半永久 | 地图本身保留，建筑可能受损 |
| **建筑** | 非永久 | 会被灾变摧毁，可重建 |

### 8.2 扩张成本

开拓新地图需要消耗 **算力配额**（由运算中心等级与数据积累换算）：

```
配额 = floor( log10(累计数据 + 1) × 中心等级 × 2 )
```

配额是**稀缺资源**，迫使玩家在"深化旧图"与"开拓新图"之间做选择。

### 8.3 旧图不废弃

- 旧地图可持续优化（升级建筑、提高抗性、扩建商路）
- 后期玩法是"运营一张网络"，而不是"不断开新档"
- 这让玩家的每一分投入都不会被重置抹掉

## 9. 灾变系统（节奏器）

保留原案的"周期性毁灭"，但改为**可预防、局部化**。

### 9.1 日冕脉冲

- 每 **N 天**（游戏内）触发一次，N 随难度 10～20 天
- 提前 1 天在日志中预警
- 对**暴露建筑**造成伤害，地下化建筑免疫

### 9.2 伤害公式

```
伤害 = 建筑最大耐久 × (1 - 抗性) × random(0.6, 1.0)
抗性 = 1 - exp(-该格累计被毁次数 / K)     // K 为调参常数
```

抗性随"被毁次数"趋近 100%，但成本趋于无穷——**失败本身成为投资**。

### 9.3 应对手段

| 手段 | 效果 | 代价 |
|------|------|------|
| 加固工程 | 抗性 +15% | 消耗金属 |
| 地下化改造 | 完全免疫脉冲 | 产出 -30% |
| 转移 | 把关键建筑搬到低风险图 | 物流成本 |
| 冗余 | 多建一套备用 | 占地与能耗 |

**设计目的**：灾变是"节奏器"和"维护压力"，不是"清档惩罚"。玩家应该有"我能扛过去"的掌控感。

## 10. 终局：月背建城

### 10.1 阶段目标

1. **发射台**：在轨道残骸带建造（需航天科技）
2. **火箭装配**：消耗大量合金、芯片、稀土
3. **燃料加注**：需要氦-3（永夜冰原）与化学品
4. **发射**：一次性事件，触发全局叙事
5. **月背着陆**：解锁月背盆地地图
6. **建城**：在真空、无光、陨石频发的环境里建立"备份城"

### 10.2 多结局

| 结局 | 触发 | 含义 |
|------|------|------|
| **备份文明** | 标准通关 | 文明被保存，AI 继续守望 |
| **留下** | 放弃发射 | 与地球共存亡，另一种选择 |
| **上传** | 特殊科技路线 | 把意识数字化，不再需要物理载体 |

### 10.3 通关后

- 开放"新周目+"：保留科技与运算中心等级，地图重新生成
- 提供更高难度的灾变参数与更稀有的资源分布

## 11. 视觉与美术方向

### 11.1 参考：WorldBox

WorldBox 的视觉特征（已核实）：**俯视视角、像素风、地形由像素方块堆砌、文明与灾害可视化、有限色板**。

我们借用其"沙盒俯视 + 像素块"的观感，但表达的是**网络**而非**造物**。

### 11.2 具体规范

| 项目 | 规范 |
|------|------|
| 视角 | 正交俯视（2D） |
| 格子 | 24×24 像素块，地图默认 24×24 格 |
| 色板 | 16 色主色板 + 4 色强调色（能量=青、灾变=橙红） |
| 建筑 | 小尺寸像素图标，2～3 帧建造动画 |
| 商路 | 格子间连线的像素光点流动 |
| UI | 终端风等宽字体 + 像素边框面板 |
| 动效 | 建造粒子、断电全局变暗、脉冲来袭屏幕震动 |

### 11.3 视觉叙事

- **断电**：画面整体降低亮度，UI 变红
- **灾变预警**：天空色调转为橙红，日志刷红字
- **网络成型**：商路连线越多，地图整体越亮——"点亮世界"的正反馈

## 12. 技术架构

### 12.1 技术选型

| 层 | 方案 | 理由 |
|----|------|------|
| 渲染 | Canvas 2D（地图）+ DOM（面板） | 像素绘制简单，UI 用 DOM 更快 |
| 逻辑 | 原生 ES Modules | 零构建，Pages 直接托管 |
| 存档 | localStorage + 版本迁移 | 无后端 |
| 大数 | break_infinity.js（超 1e15 时引入） | 尾数+指数，避免精度丢失 |
| 测试 | node --test | 零依赖 |

Settings → Pages → Deploy from branch → `main` → `/(root)`

## 13. 数值骨架

| 项 | 公式 | 说明 |
|----|------|------|
| 建造成本 | `base × 1.12^owned` | 经典几何级数 |
| 产出 | `base × count × 相邻加成 × 科技乘数` | 乘区分离，便于平衡 |
| 供电效率 | `min(1, 供给/需求)` | 缺口按比例降产 |
| 运输到达量 | `min(容量, 待运量) × (1 - 损耗)` | 每 tick 结算 |
| 抗性 | `1 - exp(-毁坏次数 / K)` | 趋近 100% |
| 灾变伤害 | `maxHP × (1 - 抗性) × rand(0.6, 1.0)` | 随机性保留 |
| 开拓配额 | `floor(log10(累计数据+1) × 等级 × 2)` | 抑制无限扩张 |

## 15. 风险与对策

| 风险 | 表现 | 对策 |
|------|------|------|
| 物流系统过重 | 玩家算不过来 | 先做线性商路，UI 用"缺口/盈余"直接提示 |
| 多地图状态爆炸 | 存档大、逻辑耦合 | 单一状态树 + `mapId` 分区，系统只读不写 |
| 像素美术成本高 | 卡在美术 | 先用色块+几何图标，跑通再替换 |
| 数值调崩 | 中期卡死或爆炸 | 所有参数外置到 `data/*.js`，可热调 |
| 范围蔓延 | 做不完 | 交付前对照第 9 节完整清单逐项核对，缺项必须显式上报 |
