## 1. 逐条说明

### 1.1 教程：修错位 + 大幅加步骤（P0）

**现象**（两条都要解决，不要只修位置）：

1. **错位**：窗口非全屏时，高亮框与目标元素对不上。
2. **步骤太少**：只有 3 步，且全是"说明"不是"动手"。同学看完仍然不知道先建什么、为什么建、建错怎么办。

#### 错位的根因（已定位）

- `tutorial.js:66-84` 的 `positionStep()` 只在 `resize` 时重算（`tutorial.js:31`），**没有监听 `scroll`**。
- 非全屏时页面出现纵向滚动条，玩家一滚动，`position: fixed` 的高亮框留在原地，目标元素却移走了。
- 另外 `positionStep()` 在移动端会先 `click()` 切换面板再立即读 `rect`，**布局还没稳定就取了坐标**。

#### 定位修复（4 条）

1. 补 `scroll` 监听（捕获阶段）：`window.addEventListener("scroll", fn, true)`，与 `resize` 一起触发重算。
2. 每步先 `target.scrollIntoView({ block: "center" })`，再在 `requestAnimationFrame` 里读 `rect`（等布局稳定）。
3. 高亮框做**视口钳制**：`left/top ≥ 0`，宽高不超出 `innerWidth/innerHeight`。
4. 目标不存在时不静默跳过，居中显示卡片并提示"未找到目标元素"。

#### 内容扩充：改成"两段式"

3 步不够，但一口气十几步也会劝退。建议拆成**必看**与**进阶**两段。

**A. 必看（4 步，强制，动作门控）**——走完才算脱离新手

| 步 | 触发条件 | 文案要点 |
|----|----------|----------|
| 1 | 自动 | 你是一台 AI 运算中心；目标：撑过百日，把文明送上月背 |
| 2 | 放下第 1 座太阳能板 | 先供电，否则一切都不转 |
| 3 | 放下第 1 座废料场 | **能源不产资源，采集才产**——这是最容易踩的坑 |
| 4 | 废钢 ≥ 20 | 资源条：左边是库存，右边是每秒净变化 |

**B. 进阶（8 条，不强制，做成侧边任务清单）**——玩家按需触发

| # | 触发条件 | 教什么 |
|---|----------|--------|
| 5 | 废钢 ≥ 60 | 建冶炼厂：加工链 废钢 → 金属 |
| 6 | 第一次断电 | 断电不是停机，是全图按比例降产 |
| 7 | 数据 ≥ 10 | 研究所解锁科技，先点「深钻」 |
| 8 | 第一次升级（原叠放） | 产出 ×1.6，但受损风险同步上升 |
| 9 | 第一次拆除 | 返还 35% 材料，不会全损 |
| 10 | 距脉冲 1 天 | 预警出现，提醒加固或地下化 |
| 11 | 解锁第二张地图 | 中转站与商路：跨图资源不共享 |
| 12 | 任意时刻 | 存档与设置：导出、重开、重看教程 |

**为什么这样分**：必看只教"活下来的最小闭环"，进阶在你真的遇到那个系统时才出现——既不劝退，也不会漏教。

### 1.2 缩放改为 Ctrl + 滚轮（P1）

**现状**：缩放靠设置面板里的 1×/2×/3× 按钮（上一轮已从顶栏移入设置）。

**方案**：

- 在 `grid.js` 的 canvas 上监听 `wheel`，`{ passive: false }`
- 仅当 `event.ctrlKey` 时接管：`event.preventDefault()`，按 `deltaY` 调整 `zoom`（1/2/3 档，或改为 1–4 连续档）
- 非 Ctrl 的滚轮保持页面正常滚动，不要抢
- 缩放时**以鼠标位置为锚点**（保证缩放后光标下的格子不变），而不是以左上角为锚点
- 设置面板里的缩放按钮保留作为**兜底**（移动端没有 Ctrl）

**注意**：`Ctrl + 滚轮` 是浏览器默认的页面缩放快捷键，`preventDefault` 能拦住，但要确认在 Chrome/Edge/Firefox 下都生效；拦不住时降级为 `Alt + 滚轮`。

**验收**：地图区 Ctrl+滚轮平滑缩放，光标下的格子不漂移；页面其余区域 Ctrl+滚轮仍能缩放页面。

### 1.5 地下挖掘（P2，新玩法）

**目标**：给中后期一个纵向扩张维度，解决"地表 24×24 建满就没事干"。

#### 数据模型

```
map.layers = [
  { depth: 0, cells: Array(576) },   // 地表，现有逻辑
  { depth: 1, cells: Array(576) },   // 地下 1 层
  ...
]
map.currentDepth = 0
```

为兼容现有代码，建议保持 `map.buildings` 指向"当前层"的数组视图，或统一改成 `map.layers[d].buildings` 并在读取处加 `layer` 参数。

#### 玩法

| 元素 | 规则 |
|------|------|
| **钻探炸药** | 一次性建筑/道具，放置后 10 秒引爆，向下打通一层 |
| **初始可用区** | 爆破点为中心的 **3×3**，其余格子为"岩层"，不可建造 |
| **地下支撑** | 常规建筑，占 1 格，把相邻 3×3 的岩层转为可用（每次扩张 +9 格） |
| **地下收益** | 采矿类产出 ×1.5；**无灰烬风暴**；但**无日照**，太阳能板产出为 0 |
| **地下风险** | 新增"塌方"事件：随机让 1 格变回岩层（建筑被埋，需重新挖） |
| **深度上限** | 建议 3 层，避免状态爆炸 |

#### UI

- 地图右侧加 **▲ / ▼** 两个按钮切换层（你提的方案）
- 当前层显示为 `灰烬平原 · 地下 -1`
- 地下层背景色明显更深，粒子更少

#### 验收

- 炸开一层后能在地下建造，产出按 ×1.5 结算
- 上下切换层时，建筑、资源、选中状态都正确
- 存档能保存多层数据（见 3.3）

### 1.6 多尺寸建筑（P2，新功能）

**目标**：让"航天设施"这类大工程有体量感，同时丰富布局策略。

#### 数据层

```js
{
  id: "launchpad",
  size: { w: 5, h: 5 },   // 默认 { w:1, h:1 }
  ...
}
```

#### 放置规则

1. footprint 内所有格必须为空、同层、在界内
2. 放置时：锚点格存完整 building，其余格存 `{ anchor: anchorIndex }` 占位
3. 拆除：只允许点锚点，删除时清空整个 footprint
4. 相邻加成：按 footprint **外沿相邻格**计算，不按内部格
5. 伤害：按锚点结算一次（现在 `applyDamage` 会对每个 index 结算，必须跳过 `anchor` 占位格，否则大建筑会被重复扣血）

#### 建议尺寸分配

| 尺寸 | 建筑 |

| 2×2 | 装配厂、芯片厂、数据核心 |
| 3×3 | 轨道电梯、燃料厂 |
| 5×5 | 发射台、火箭装配厂 |

#### 验收

- 5×5 建筑能正确放下，边界外/重叠时给出明确提示
- 一次脉冲只扣一次血
- 拆除 5×5 后 25 格全部清空

### 1.10 卡片点不上 + 缺料整卡变红（P0）

**现象**：有时点建造卡片没反应。

**根因（已定位）**：`hud.js:349-360` 的 `renderBuildList()` 用 `innerHTML =` **整块重建**，而它会被 `render()` 在**每个 tick** 调用（`hud.js:331`）。玩家 `pointerdown` 与 `pointerup` 之间如果恰好跨过一次重建，DOM 节点已被替换，`click` 事件就丢失了。窗口越小、渲染越频繁，越容易复现。

**方案**：

1. **不要每 tick 重建卡片列表**。只在建筑解锁状态变化、资源跨过可负担阈值、选中项变化时才重建。
2. 或者改为**事件委托**：容器上挂一个 `click`，通过 `event.target.closest("[data-building]")` 判定，DOM 重建也不影响。
3. 选中卡片时不要整表重建，只切换 `.selected` 类。
4. **缺料整卡变红**：给卡片加 `.unaffordable` 类（红色边框 + 红色成本文字），替代现在右下角的小字"缺料"。

**验收**：快速连点 20 次建造按钮，20 次全部响应；资源不足的卡片整体呈红色。

### 1.13 生物质被下游吃满（P2）

**结论：零和截断是正确设计，不改结算逻辑。**

`production.js:82-99` 的行为是：库存为 0 且消耗 ≥ 产出时，把消耗压到恰好等于产出，净变化为 0。这在物理上是对的——需求大于供给时，本来就不该有积累。

**但玩家会误读**：资源条显示 `生物质 0 · -0.0/s`，看起来像"反应器没工作"。所以只做两件小事。

#### 1. 可选：显示毛产出 / 毛消耗

不动结算，只在资源条把净值拆开：

```
生物质   0    +6.0 / -6.0   ← 全部被下游消耗
```

`diagnose.js` 可增加一类提示：`上游产出被下游吃满`。

#### 2. 微调产出效率，制造可见盈余

关键机制：只要**产出 > 消耗**，`factor` 就会变成 1，库存开始正积累；一旦 `产出 ≤ 消耗`，净值恒为 0。所以只需把产出抬高一点，就能从"恒为 0"变成"缓慢上涨"。

| 方案 | 改动 | 效果 |
|------|------|------|
| **A（推荐）** | 生物反应器 `produce.biomass: 1 → 1.25` | +25%，盈余可见，不破坏平衡 |
| B | 生物反应器 `1 → 1.5` | +50%，积累明显，可能让化工厂过剩 |
| C | 化工厂 `consume.biomass: 2 → 1.6` | 等效于降消耗，副作用更小 |

**怎么判断调够了**：建 6 座反应器 + 3 座化工厂时，生物质应**持续缓慢上涨**，而不是卡在 0。若仍为 0，说明配比还是相等，继续微调。

> 注意：产出与消耗都会被 `1.6^(等级-1)` 与相邻加成放大，**比例取决于升级等级，不是建筑数量**。所以要在"接近同等级"的前提下测。

**验收**：合理配比下生物质能持续上涨；即便被吃满，也能从界面看出"在产但被消耗"，而不是"没产"。

### 1.15 日冕脉冲伤害太弱（P1）

**现状**：`disaster.js:27-35` 的伤害是

```
damage = maxHp × (1 - 抗性) × rand(0.6, 1.0) × 堆叠风险 × difficulty
```

按公式，无抗性、未堆叠、difficulty=1 时单次伤害应为 **60%~100% 最大耐久**——理论上第一发就该清掉大半。但实测几乎没有建筑被摧毁，说明**链路上某处没生效**，而不是数值太小。

**先定位，再调参**（顺序不能反）：

1. 脉冲结算时输出日志：`本次脉冲：N 座受损，M 座摧毁，总耐久损失 X%`
2. 检查 `getBuildingResistance()` 是否返回了非预期的高抗性（例如把"加固工程"的加成算成了全局）
3. 检查 `applyDamage` 是否被 `underground` 或 `anchor` 提前 return
4. 检查 `difficulty` 实际取值（新档默认 1，周目+ 会递增）

定位后再按你的目标调整：

> 单次脉冲对**无抗性建筑**造成 **50%~70% 最大耐久**伤害，即两发基本清场；对抗性建筑递减。

**验收**：第一次脉冲后，日志能明确写出损毁数量，且与画面一致。

### 1.16 灰烬风暴过频 + 缺特效（P1）

**现状**：`disaster.js:66-69`

```js
STORM: until = elapsed + 15, nextHazard = elapsed + 60
```

即**每 60 秒一次、每次持续 15 秒**——占用了 25% 的游戏时间，非常频繁。

**方案**：

| 项 | 现值 | 建议 |
|----|------|------|
| 间隔 | 60s | **180~300s**（3~5 个游戏日） |
| 持续 | 15s | 20~30s（但要变稀有） |
| 减产 | 50% | 保持 50%，或改为 60% 但更短 |

**视觉**：现在只是整体变暗。建议加：

- 屏幕边缘灰色粒子（Canvas 粒子层，`render/fx.js`）
- 建筑上方轻微尘雾（低透明度、低频）
- 进入/退出风暴时各 0.5 秒淡入淡出
- 注意性能：粒子数 ≤ 120，`prefers-reduced-motion` 时关闭

**验收**：风暴明显变稀有；出现时有可辨识的粒子动效，且不卡顿。
