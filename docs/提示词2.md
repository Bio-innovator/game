## 2. 第一步：先同步仓库（不许跳过）

### 2.1 当前状态：本地与远端已经分叉

- 本地 `main` 有 **4 个未推送提交**
- 远端 `main` 有 **本地没有的提交**（新增 LICENSE、重写 README）
- 因此 `git push` 会直接被拒

### 2.2 同步步骤（按顺序执行）

```bash
git fetch origin
git status -sb          # 确认 diverged，而不是 ahead only
git pull --rebase origin main
```

**如果 `README.md` 冲突（几乎一定会冲突）：**

```bash
# 关键：一律用远端版本覆盖本地
git checkout origin/main -- README.md
git add README.md
git rebase --continue
```

**为什么必须这样**：本地 README 里有「运行 / 测试 / 结构 / 部署」四节，作者已明确表示**这些不需要放到 GitHub 上**。远端版本是他手动删减后的结果。所以：

> **以远端 README 为唯一基线，覆盖本地，然后在这个基础上改。**

不要"合并两边内容"，不要"把删掉的段落加回去"。

### 2.3 同步完成后自检

- [ ] `git status -sb` 显示 `up to date`（不再 ahead / behind）
- [ ] 本地 `README.md` 内容与远端一致（只有「标题 + 链接 + 操作 + 核心规则」这几节）
- [ ] 本地能看到 `LICENSE` 文件
- [ ] `npm test` 仍然全绿

## 3. 硬约束（违反任一条即视为不合格）

1. **不换技术栈**：继续用原生 ES Modules、零构建、无框架、无 CDN。
2. **不加依赖**：不引入任何 npm 运行时依赖；需要库就自己写。
3. **不改数值平衡**：`DAY_SECONDS` 保持 `60`；建筑成本/产出/脉冲间隔一律不动。唯一允许动的是"离线不再结算"。
4. **不删测试**：现有测试必须继续通过；新增功能要补测试。
5. **不改存档版本号**：除非确实需要迁移，且必须写清迁移逻辑。
6. **相对路径**：所有引用保持相对路径，`/<repo>/` 子路径下不得 404。
7. **无控制台报错**：交付时 `0 error`。
8. **一次交付完整改动**：不要只做第 1 批就跑来问"要不要继续"。
9. **不改游戏名**：仍为《百日之城 / Hundred-Day City》。

**改动点**：

**验收**：关闭页面 1 小时后打开，`day`、各图资源、建筑数量与关闭时**完全一致**。

**目标**：玩家随时知道"为什么不动了"。

**改动点**：

- 新增 `src/systems/diagnose.js`，输入 state、输出 `{ code, text }`
