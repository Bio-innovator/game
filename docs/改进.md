### 1.2 离线改为完全暂停（P0）

**你的决定**：离线期间游戏**完全暂停**——不结算资源、不推进天数、不触发灾变。这是最干净的做法。

**现状**（`src/main.js:11, 37-43`）：

```js
const offlineResult = loaded ? settleOffline(state, loaded.offlineSeconds) : null;
...
if (offlineResult) { ... offlineDialog.showModal(); }
```

`settleOffline`（`src/core/tick.js:30-65`）按"资源前后差值"计算收益，而 `OFFLINE_TIME` 会把离线秒数直接加进 `state.elapsed`（`src/core/state.js:378-389`）。于是出现两个问题：

- 只建能源站 → 差值 0 → 弹窗显示"无净产出"，按钮却叫"接收离线收益"
- 离线 8 小时 → 天数 +480，且脉冲计时被重置

**改法**：把"结算"整个删掉，只保留"续档询问"。

1. **不再调用 `settleOffline`**：`main.js` 第 11 行改为只读取 `loaded`，不做结算。
2. **不再派发 `OFFLINE_TIME`**：`state.elapsed` / `day` 保持不变。
3. **弹窗改为二选一**：

| 位置 | 文案 |
|------|------|
| 标题 | 继续上次的存档？ |
| 正文 | 上次记录：周目 X · DAY Y · 建筑 Z 座。离线期间游戏不会运转。 |
| 主按钮 | **继续本局** |
| 次按钮 | 开始新游戏（二次确认，清除存档） |

4. **`index.html:107-111`** 的 `offline-dialog` 要改：去掉 "UNSUPPORTED TEMPORAL EVENT" 这种科幻标签，改成普通对话框；按钮 id `offline-close` → `offline-continue`。
5. **清理死代码**：`settleOffline`、`MAX_OFFLINE_SECONDS`、`OFFLINE_TIME`、`logs.js:92-95` 的 offline 文案都不再被使用。可以删除，或保留并加注释「已停用」。
6. **README 同步**：远端那句"离线收益最多结算 8 小时；离线期间不追溯灾变损伤"必须删掉，改成"**关闭页面后游戏暂停，不产生离线收益**"。

**为什么这个选择是对的**：

| 原问题 | 离线暂停后 |
|--------|-----------|
| 弹窗"收益 0"自相矛盾 | 不存在了，本来就没有收益 |
| 挂机 8 小时 = 480 天 | 天数不再跳变 |
| 挂机绕过灾变，越挂越安全 | 离线等于暂停，风险对称 |
| 要解释"离线怎么算" | 一句话：关掉就是暂停 |

**验收**：关闭页面 1 小时后重新打开，天数、资源、建筑与关闭时**完全一致**；弹窗只问"是否继续"。

### 1.3 新手教程 + 重新开始（P0）

**现状**：

- 没有任何首次进入引导；
- **没有全局"重新开始"按钮**；
- `clearSave()` 在 `src/save/storage.js:153` 已定义，但**全项目没有任何地方调用它**（死代码）。

**问题**：你描述的"一上来把铁全建成能源站，只能等死"——这是**信息缺失**导致的必然结果，不是玩家失误。

**建议做法**：

**A. 首次运行引导（3 步遮罩）**

```
if (!localStorage.getItem("hdc-tutorial-done")) {
    // 第一步：高亮左侧建造面板 → "先选一个蓝图"
    // 第二步：高亮地图 → "点击空格建造"
    // 第三步：高亮顶栏能量 → "供给低于需求，就会降产"
}
```

- 用 `position: fixed` 的半透明遮罩 + 高亮框，不引入任何库
- 三步走完写入 `hdc-tutorial-done = 1`
- 设置面板里提供「重看教程」入口

**B. 重新开始按钮**

放在**设置面板底部**，红色危险样式，必须二次确认：

> 这会清除当前进度（周目、地图、科技、存档）。确定吗？
> [取消] [确认重开]

实现：`clearSave()` + `location.reload()`。不要复用 `NEW_GAME_PLUS`（那是保留科技的周目+，语义不同）。

**C. 防死局兜底**（重要）

即使加了重开，也要让玩家**不必**重开：

- 拆除功能已有（见 2.2），但入口要显眼
- 建议增加：当**所有地图资源均为 0、无在产建筑、无在建建筑**时，日志提示一次「网络已停摆，可拆除能源站回收材料，或重新开始」

**验收**：新玩家不看 README 也能在 60 秒内建出第一条产线；任何时候都能在两分钟内重开。

### 1.4 一天 = 60 秒（已确认，保持不变）

**当前事实**（`src/data/maps.js:3`）：

```js
export const DAY_SECONDS = 60;
```

| 速度 | 1 游戏日 | 100 日（"百日"） |
|------|----------|------------------|
| 1× | **60 秒** | **100 分钟** |
| 2× | 30 秒 | 50 分钟 |
| 4× | 15 秒 | 25 分钟 |

**你的决定**：**保持不变**。理由是和整体平衡绑定——成本曲线、脉冲间隔、建筑时长都是按这个节奏调出来的，动它会连锁影响数值。

在「离线完全暂停」之后，这个数值反而变得合理了：**"百日" = 约 100 分钟的主动游玩**，不会再被挂机跳成 480 天。这一条从"需要拍板的设计问题"降级为"确认并写进文档"。

**要做的只有一件事**——在 README 里写清楚：

> 1 游戏日 ≈ 60 秒（1× 速度）；100 日 ≈ 100 分钟。关闭页面后游戏暂停，日序不会推进。

**验收**：README 的表述与 `DAY_SECONDS` 一致，玩家不会误以为"100 天 = 100 个现实日"。

### 1.5 导出 / 导入不完善（P1）

**现状**（`src/render/hud.js:395-422`）：

- 导出 = 生成 Base64 塞进 `<textarea>` + 自动全选 + toast 提示"请复制保存"
- 导入 = 粘贴文本 → `decodeSave` → `migrateAndValidate` → 直接替换当前进度
- 校验比较完整：版本号、字段类型、坐标范围、地图白名单都做了

**缺的部分**：

| 缺失 | 影响 | 建议 |
|------|------|------|
| 没有一键复制 | 用户可能复制不全 | `navigator.clipboard.writeText()` + 降级到 `select()` |
| 不能存成文件 | 长文本在聊天工具里容易被截断 | 提供「下载 .txt」；导入支持 `<input type="file">` |
| 导入前无确认 | 误点即覆盖，且不可撤销 | 弹确认框，显示存档摘要：周目 / 天数 / 建筑数 / 保存时间 |
| 导入前无备份 | 覆盖后原档永久丢失 | 覆盖前先写 `localStorage["hdc-save-backup"]` |
| 失败无回滚 | 导入异常可能半途改状态 | 先完整解析成新 state，成功后再整体替换 |

**建议的存档面板结构**：

```
[当前进度摘要]
周目 1 · DAY 42 · 建筑 37 · 科技 9/12 · 最后保存 19:03

[导出]
[复制到剪贴板] [下载存档文件]

[导入]
[选择文件] 或 粘贴文本
→ 预览：周目 1 · DAY 42 · 建筑 37
→ [确认覆盖]（会先自动备份当前进度）
```

**验收**：导出→清缓存→导入，进度完全一致；导入前一定能看到"你要覆盖的是什么"。

### 1.7 字体有"AI 味"（P1）

**现状**（`assets/style.css:15`）：

```css
font-family: "Cascadia Mono", "SFMono-Regular", Consolas, "Liberation Mono", monospace;
```

**诊断**——"AI 味"不是错觉，来源有三个：

1. **全站等宽字体**：中文没有等宽字形，会回退到系统字体（微软雅黑 / 苹方），导致中英文**字重与基线不一致**，看起来"拼贴感"很强；
2. **全大写英文标签**（`CONSTRUCTION` / `ARCHIVE TERMINAL` / `SYSTEM`）+ 大字距，是典型的"科技感模板"写法；
3. **字号过小**（8～11px）+ 纯冷灰色，信息密度高但可读性差。

**建议**：

| 用途 | 字体 | 理由 |
|------|------|------|
| 正文 / 按钮 | `system-ui, "PingFang SC", "Microsoft YaHei", sans-serif` | 中文走系统黑体，视觉统一 |
| 数字 / 日志 / 资源 | `"Cascadia Mono", Consolas, monospace` | 数字对齐仍然需要等宽 |
| 标题（可选） | 像素字体，vendor 一个 woff2 | 强化像素风 |

具体动作：

- 把 `body` 的 `font-family` 改成无衬线中文栈，**只给 `.log-stream`、`.stat strong`、资源数字**加等宽；
- 去掉全大写 English eyebrow，或改成小写 + 缩小字距；
- 基准字号从 10px 提到 **13px**，行高 1.6；
- 若要用像素字体：**必须自托管 woff2**（不能用 CDN，违背"零外部依赖"），且中文像素字体（如 Zpix）需先确认授权。

**验收**：截图给一个没看过项目的人，问"这像人做的还是 AI 生成的"。

### 1.8 明暗主题切换（P2）

**现状**：`assets/style.css:3` 只有一套 `--bg: #101216`；`assets/palette.js` 也只有一套深色色板。

**好消息**：DOM 部分已经是 CSS 变量驱动，加 `[data-theme="light"]` 覆盖即可，工作量很小。

**难点在 Canvas**：地图是用 `palette.js` 里的常量绘制的，切主题时 canvas 不会跟着变。两条路：

| 方案 | 做法 | 评价 |
|------|------|------|
| **A. 双色板（推荐）** | `palette.js` 拆成 `DARK` / `LIGHT` 两套，`grid.js` 每帧取当前主题 | 效果最好，改动集中在 palette + renderer |
| B. CSS 滤镜 | 对 canvas 施加 `filter: invert()` / `hue-rotate()` | 一秒实现，但颜色会失真、像素描边变脏 |

**实现要点**：

1. `state.settings.theme = "dark" | "light"`
2. **必须扩展 `src/save/storage.js:118-122`**——目前只持久化 `zoom / speed / paused`，不加就会"切换后刷新丢失"
3. Canvas 重绘时机：主题切换时强制 `grid.render()`
4. 默认跟随系统：`matchMedia("(prefers-color-scheme: light)")`

### 2.2 拆除入口太隐蔽（P0）

**现状**：拆除**已经实现了**，而且逻辑不错——返还 35% 基础材料（`src/core/state.js:494-505`）。入口在选中格子后的面板里（`src/render/hud.js:306`）：

```html
<button data-cell-action="dismantle" class="danger">拆除</button>
```

**问题**：必须**先点中一个格子**才会出现。玩家在"建错了、想挽回"的慌张状态下，根本不会想到去点格子。

**建议**（三选一或组合）：

1. 建造面板顶部加一个「**拆除模式**」开关，开启后点任意建筑即拆（带 35% 返还提示）；
2. 首次拆除前弹一次提示：「点击地图上的建筑 → 右下角可拆除，返还 35% 材料」；
3. 新手引导第三步就讲这件事。

---

### 2.3 停产无诊断（P1）

**现状**：顶栏只显示 `能量 0 / 0`，日志偶尔刷"限电"，但**玩家不知道该修什么**。

**建议**：在资源条或顶栏加一个「状态」指示，用一句话说明当前卡在哪：

| 判定顺序 | 提示文案 |
|----------|----------|
| 全图无采集建筑 | 没有采集节点，资源不会增长 |
| 供给 < 需求 | 电力不足，全图产出降至 X% |
| 有在产建筑但原料为 0 | 缺少原料（如冶炼厂缺废钢） |
| 所有建筑都在建造中 | 等待建造完成 |
| 正常 | 网络运转中 |

这条比任何教程都有效——它让玩家**随时能自己诊断**。

### 2.4 存档安全（P1）

见 1.5。这里单独强调一个**不可逆风险**：

`importSave()`（`hud.js:409-422`）在校验通过后**直接 `replaceState` 覆盖当前内存状态**，而 `replaceState` 内部会立刻 `saveGame`。也就是说：

> 一旦误粘贴了别人的存档，你的进度会被**立即写盘覆盖**，且没有备份。

**必须加**：覆盖前把当前存档写入 `localStorage["hdc-save-backup-<timestamp>"]`，并在设置里提供「恢复上一份备份」。

### 2.5 离线推进天数与"百日"冲突（P0，已定方案）

**问题回顾**：`OFFLINE_TIME` 会把离线秒数直接加进 `state.elapsed`（`src/core/state.js:378-382`），8 小时上限 = 28,800 秒 = **480 天**。而且它还会重置脉冲计时（`state.js:381-387`），等于离线不仅跳过天数，还跳过了所有灾变——**挂机越久越安全**，与"灾变是节奏器"的设计完全相反。

**已定方案**：离线**完全暂停**（见 1.2）。不结算、不推进、不重置。

三个问题一次解决：

- "百日"不再被挂机架空
- 灾变节奏只由主动游玩决定
- 玩家不需要理解任何"离线折算"规则

**落地清单**：

- [ ] 删除 `main.js` 对 `settleOffline` 的调用
- [ ] 删除或停用 `OFFLINE_TIME` 分支
- [ ] 清理 `MAX_OFFLINE_SECONDS` 与 `logs.js` 的 offline 文案
- [ ] README 删除"离线收益最多结算 8 小时"

### 2.6 移动端地图操作（P2）

**现状**：canvas 固定 576×576，移动端靠 `.canvas-scroll` 横向滚动。

**问题**：24×24 格在手机上只能看到局部，且**滚动与点击容易冲突**（想拖动变成了建造）。

**建议**：

- 双指缩放（pinch）+ 单指拖拽平移
- 或提供"自适应屏幕"档位（整图缩放到宽度）
- 建造时加"确认点击"，避免误触

### 2.7 可访问性（P2）

- `prefers-reduced-motion`：关闭屏幕抖动与粒子（对光敏感用户很重要）
- 键盘操作：方向键移动选中格、Enter 建造、Esc 取消
- 对比度：当前灰色文字在小字号下对比度偏低
- 字号可调（结合 1.6 的设置面板）

### 2.8 性能（P2）

**现状**：`grid.js` 每帧重绘整张 24×24 地图 + 所有建筑 + 商路 + 粒子。当前地图规模下没问题，但：

- 6 张地图全部解锁后，如果切换地图仍全量重绘，会有明显掉帧
- 建议：**分层 canvas**（地形层静态缓存 / 建筑层按需重绘 / 特效层每帧清空），或至少把地形渲染到离屏 canvas 后只 `drawImage` 一次
