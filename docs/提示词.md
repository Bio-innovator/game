## 3. 视觉与美术（这是本项目的重点之一）

### 3.1 风格定义

参考 **WorldBox（世界盒子）** 的观感：**正交俯视、像素块地形、有限色板、方块堆砌出体积感、灾害有明确画面表现**。

但我们表达的是**网络**而非**造物**：
- WorldBox 是"上帝撒地形、看文明打架"
- 我们是"建节点、连商路、点亮点阵"

**只学风格与观感，不要复制其任何素材。**

### 3.2 分辨率与色板

| 项目 | 规范 |
|------|------|
| 地形 tile | 24×24 px |
| 建筑精灵 | 16×16 px（大型建筑可用 16×32） |
| UI 图标 | 8×8 或 16×16 px |
| 缩放 | **整数倍**（1x/2x/3x），禁止小数缩放 |
| 主色板 | 16 色（冷灰、锈褐、暗绿、土黄为主） |
| 强调色 | 能量 `#3FD0C9`（青）、灾变 `#E0533D`（橙红）、科研 `#B48CE0`（紫） |
| 渲染 | `ctx.imageSmoothingEnabled = false`；CSS `image-rendering: pixelated` |

### 3.3 素材怎么生成（四选一，推荐 A）

**方案 A：程序化像素矩阵（推荐，零外部依赖）**

用字符串矩阵定义精灵，运行时渲染到 Canvas 或转成 dataURL 缓存。优点：可版本控制、易改色、体积小、无需外部工具。

```js
// assets/sprites/buildings.js
export const PALETTE = {
  '.': null,
  '1': '#1E1E22',  // 描边
  '2': '#4A4A52',  // 暗部
  '3': '#8A8A96',  // 亮部
  '4': '#3FD0C9',  // 能量
};

export const SOLAR_PANEL = [
  '..111111..',
  '.13333331.',
  '1333333331',
  '1344444431',
  '1333333331',
  '.13333331.',
  '..111111..',
  '...1111...',
];
```

渲染时逐像素 `fillRect`，或先画到离屏 canvas 再 `drawImage`。**必须缓存**，不要每帧重绘。

**方案 B：CSS 像素画**
用 `box-shadow` 多点绘制小图标，或用 `background-image` + `background-size` 整数倍放大。
适合 UI 按钮、状态图标。

**方案 C：SVG 像素块**
用 `<rect>` 网格拼图，天然矢量、放大不糊。适合需要大尺寸展示的图鉴、标题界面。

**方案 D：外部工具导出 PNG 图集（可选升级路径）**
Aseprite / LibreSprite / Piskel 绘制，导出 `spritesheet.png` + `spritesheet.json`（帧坐标）。
适合后期替换为更精致的正式美术。**若采用此方案，必须在仓库内提供源文件与生成脚本说明。**

**本项目要求**：以 **方案 A** 为默认，保证开箱即用、无外部依赖；在 `assets/sprites/` 下按类别分文件。

### 3.5 动画要求（至少实现三种）

1. **建造中**：半透明轮廓 + 自下而上填充的进度
2. **产出中**：建筑上方周期冒出 1px 像素点（资源色）
3. **灾变**：全屏橙色闪 2 帧 + 屏幕抖动 + 受影响格子闪红

用帧计数驱动，不要依赖 CSS transition 做像素动画（会导致非整数缩放模糊）。

### 3.6 UI 风格

- 等宽像素字体（可用系统等宽字体 + `font-smooth: never`）
- 面板：2px 实线边框 + 深色底，禁止圆角、禁止渐变、禁止阴影模糊
- 顶栏：能量（供给/需求）、数据、当前天数、灾变倒计时
- 左侧/底部：建筑选择栏（图标 + 名称 + 成本）
- 右侧：日志（可折叠）
- 弹窗：科技树、地图切换、存档管理

### 3.7 禁止事项

- 禁止使用真人照片、AI 写实图、渐变、模糊阴影、圆角
- 禁止非整数缩放（会让像素糊成一团）
- 禁止从网上直接扒图；所有素材必须可溯源（自绘或程序生成）

## 6. 系统规格

### 6.1 资源（5 层）

| 层 | 资源 | 作用 |
|----|------|------|
| 驱动 | `energy` | 所有建筑运行前置，**断电即降产** |
| 物质 | `steel` 废钢、`metal` 金属、`rare` 稀土、`biomass` 生物质、`chem` 化学品、`chip` 芯片 | 建造与加工 |
| 信息 | `data` 数据 | 科研货币 |
| 物流 | `capacity` 运力 | 地图间运输上限 |
| 终局 | `helium3` 氦-3、`fuel` 燃料 | 火箭与月背 |

### 6.2 能量规则（必须实现）

```
supply = Σ(能源建筑产出 × 地图系数)
demand = Σ(所有建筑能耗)
if demand > supply:
    efficiency = supply / demand        # 全图按比例降产，不是停机
    if 连续 30s 供不应求: 触发 "限电"，高能耗建筑优先停机
```

### 6.5 物流与商路（核心差异化，必须实现）

- 每张已开拓地图有且仅有 1 座中转站
- 中转站之间可建商路，三参数：**容量 / 延迟 / 损耗**
- 升级链：车队 → 管道 → 轨道电梯
- 商路可被灾变切断，需要冗余路径
- **实现简化**：只做 A↔B 直连，不做多跳寻路；运输用"每 tick 配额"而非逐件模拟

### 6.6 灾变（节奏器，不是清档）

```
每 N 天（10~20）触发一次日冕脉冲，提前 1 天日志预警
damage = maxHP × (1 - resistance) × rand(0.6, 1.0)
resistance = 1 - exp(-该格累计被毁次数 / K)
```
- 地下化建筑免疫，但产出 -30%
- 灾变**不得清空存档**，只损伤建筑

### 6.7 科技树（至少 12 项）

四支：`能源` / `加工` / `物流` / `航天`。每项消耗 `data`，解锁建筑或提升乘数。必须有可视化树状界面。

### 6.8 终局

发射台 → 火箭装配 → 燃料加注 → 发射 → 月背着陆 → 建城。
三个结局：**备份文明** / **留下** / **上传**，各有独立结算画面。
通关后开放"新周目+"（保留科技，地图重生成）。

## 8. 编码规范

1. **数据驱动**：建筑/地图/科技/日志全部放 `data/*.js`，系统层不硬编码内容。
2. **单向数据流**：系统函数只读 state，所有写入集中在 reducer 或 `apply()`。
3. **固定步长**：`requestAnimationFrame` + 累积 delta，逻辑 tick 固定 100ms，渲染可插值。
4. **大数**：超过 `1e15` 切换到 `Decimal`（自实现尾数+指数，或 vendor `break_infinity.js`），禁止出现 `Infinity`。
5. **像素渲染**：`imageSmoothingEnabled = false`；精灵缓存到离屏 canvas，不每帧重建。
6. **离线结算**：`收益 = 速率 × min(离线秒数, 8×3600)`，回来展示"欢迎回来"面板并指向可买项。
7. **命名**：文件小写短横线，变量 camelCase，常量 UPPER_SNAKE。

## 10. 交付前自审（硬性，不许跳过）

**这一节不是建议，是门槛。**

你要假设：我打开你的成品，第一件事就是按下 F12。
如果你交上来一个控制台飘红、按钮点了没反应、存档一刷新就没的东西，还跟我说"已完成"——那这次交付就是失败的，没有第二次解释的机会。

**规则：**

1. 你必须自己**从开局完整玩到结局**，不是跑到第一张地图就说"可以了"。
2. 你必须逐条走完下面的清单，**任何一条没过，就修到过为止**。
3. 修不了，就在交付报告里**明说哪条没过、为什么**。不许静默降级，不许把"应该能跑"当成"跑过了"。
4. **禁止**留 `TODO`、空函数、假数据、写死的占位符、被注释掉的死代码。
5. 如果你只完成了 80%，就说 80%，不许说"基本完成"。

**自审清单（逐条打勾，并写明你如何验证的）：**

- [ ] 用 HTTP 服务打开，控制台 **0 error、0 warning**
- [ ] 从开局到发射，**完整跑通一次**，中途无报错、无卡死
- [ ] 断电时产出**按比例下降**，UI 有明显提示，恢复供电后自动回升
- [ ] 刷新页面，进度**不丢失**
- [ ] 导出存档 → 清空 localStorage → 导入 → 进度恢复
- [ ] 界面无 `NaN` / `Infinity` / `undefined` / `[object Object]`
- [ ] 部署在 `/<repo>/` 子路径下，资源**不 404**
- [ ] 手机尺寸下可点击、不误触缩放、面板不溢出
- [ ] 每个按钮点击都有**即时反馈**（不是点了没反应）
- [ ] 像素在 2x/3x 缩放下**不模糊**
- [ ] 100 个建筑时**不卡顿**（掉帧明显就算不过）
- [ ] 灾变有预警、有损伤、**不清档**
- [ ] 至少一条跨图物流链**真实跑通**（A 产 B 用）
- [ ] 数值曲线可玩：不会 5 分钟卡死，也不会 5 分钟通关
- [ ] `git status` 干净，所有改动**已提交并推送**到 `main`
- [ ] GitHub Pages 线上地址能打开，且是最新版本（不是旧缓存）

**交付时必须附一份《自审报告》**，格式：

```
## 自审报告
- 控制台：通过 / 未通过（说明）
- 完整通关：通过 / 未通过（说明）
- 断电降产：通过 / 未通过（说明）
...
- 未完成项：无 / 列出
- 已知问题：无 / 列出
```

**如果你发现需求之间有冲突，或某功能客观无法实现，不要偷偷砍掉——在报告里写清楚，并给出你的取舍方案。**

## 13. 现在开始

在写第一行代码之前，先用一句话回答我：

> 断电时会发生什么？

正确答案必须是"**按比例降产**"，不是"停机"，也不是"游戏结束"。

确认后，一次性实现完整版本。**不要问我"要不要先做第一阶段"——没有第一阶段，只有成品。**
